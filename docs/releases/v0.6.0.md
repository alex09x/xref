# XRef v0.6.0

**Find a constant by value, read a large function as its calls, follow
reachability through `dyn` calls, name enum arms and serialized keys, and see
which call stacks hold a live process's memory.**

## Constants by value (`xref const`)

```sh
xref -b ./app const --f64 1e9
xref -b ./app const --bytes 0x00112233445566778899aabbccddeeff00112233
```

- `const` takes a value instead of its address: `--f64`, `--f32`, `--u64`,
  `--u32` or `--bytes`. It lists the aligned copies of its bytes in data
  outside function code with the instructions that load each copy, most used
  first, and immediates carrying the same bits
  (`movabs rax, 0x3ff028f5c28f5c29`, `mov eax, 0x3f800000`).
- `--bytes` also lists the 16-, 8- and 4-byte pieces code compares the byte
  string in, and the functions using them.

See [docs/cli/const.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/const.md).

## Calls in order and reachability (`calls --order`, `path`)

```sh
xref -b ./app calls 0x401230 --order
xref -b ./app path 0x401230 --to-any 0x402000,0x403000 --depth 4
xref -b ./app path 0x401230 0x402000 --via-vtables
```

- `calls --order` prints the function's pseudo-C reduced to its calls and the
  `if`/`while`/`for`/`switch` blocks, labels and jumps around them; a `goto`
  back to a label already passed is marked `/* loop back */`. A guard whose
  variable came from a dropped load names that load, so it reads on its own.
- `path --to-any` reports which of many functions or code addresses one
  function reaches within `--depth`, each with its shortest chain.
- `path --via-vtables` also follows `dyn` calls (`call [reg+off]`) to every
  vtable method stored at that offset. These are candidate edges (any
  implementor of the trait) and are marked `?` in the chain.
- With `0 paths`, `path` says how many functions FROM reaches, how many
  indirect calls among them it could not follow and the nearest ones; then,
  on the side of TO, which functions reaching it have their address taken
  and could be entered by such a call.
- The call graph resolves `call reg` through a slot load
  (`mov r12, [rip+slot]` ... `call r12`) when the register is not written in
  between; calls through import slots count as external.

See [docs/cli/calls.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/calls.md) and
[docs/cli/path.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/path.md).

## Enum arms and serialized keys (`variant`, `disp --who-serializes`, `layout`)

```sh
xref -b ./app variant 0x401230 218-222 345
xref -b ./app variant 0x401230 --names-from 0x404000
xref -b ./app disp 0x20 0x40 --who-serializes --in 0x401230
```

- `variant` with no indices lists every index of every table in the
  function; `218-222` is an inclusive range and `--table` keeps one table.
  Each arm says what it does: the calls and tail jumps inside it, or the jump
  into shared code. For a dispatcher this is its case-to-handler table.
- `variant --names-from FN` names each index after a function that writes
  the enum's variant names (its `Display`, `Serialize` or `Debug`), matched
  through the tag value when both tag loads are found.
- Jump tables end at the dispatch's range check and before the next address
  the function references, so adjacent tables of one `match` are no longer
  read into each other.
- `(ptr, len)` string literals are cut to their length, so packed Rust
  literals show as `"e"` instead of running into their neighbours.
- `disp --who-serializes` names the key each displacement is serialized
  under: a call passing a `(ptr, len)` key literal together with the field,
  including through a small helper, or "not serialized".
- `layout` lists the constants each field is tested against (`cmp 0x2`,
  `test 0x1`, `nonzero`).

See [docs/cli/variant.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/variant.md),
[docs/cli/disp.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/disp.md) and
[docs/cli/layout.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/layout.md).

## Live memory by call stack (`xref live heap`)

```sh
sudo xref -b ./app live heap --pid PID --duration 10m --interval 30s --out heap/
xref -b ./app profile report heap/heap-0003.xprof --within 0x401230
```

- `live heap` follows the memory syscalls of every thread (`mmap`, `munmap`,
  `mremap`, `brk`, `mprotect`) through kernel tracepoints, copies the user
  stack at each one that maps memory, unwinds it from `.eh_frame` and reports
  the stacks by the bytes they still hold. There is no `malloc` uprobe, so
  the process keeps its speed.
- `--interval` writes `.xprof` snapshots; `profile report` ranks a heap
  snapshot by bytes, `--within FN` lists the bytes under each callee of FN,
  and `profile diff` compares two snapshots.
- Profile reports demangle Rust names (legacy and v0), and a demangled name
  copied from a report works wherever a function name is accepted.
- Only memory mapped while xref observes is attributed; see the limits on
  the reference page.

See [docs/cli/live-heap.md](https://github.com/alex09x/xref/blob/v0.6.0/docs/cli/live-heap.md).

## Other live changes

- `live memscan --range LO HI [--width 4|8]` matches every aligned word in a
  value range and prints the value found.
- `live watch` reports the least and greatest value each writer stored;
  `--value-range` keeps only samples in a range, `--max-samples` sets how many
  are kept and `--json-lines` streams every passing hit.
- `live probe` selects the tracefs backend by itself when a tracefs-only
  option (`--fetch`, `--filter`, `--every`, ...) is given, and `--fetch`
  accepts `%rcx`-style register names.

## Pseudo-C, matching and diffs

- `c` names recognised library code: a `HashMap` entry get-or-compute callee
  (the compute and insert functions), and an inlined chrono
  `timestamp_millis` as `ms = timestamp_millis(date, secs, nanos)` with its
  inputs.
- At a call receiving `&slot_N`, a comment names the stack object stored
  right before it, with the values it holds at that point.
- `match` checks for the same instruction stream (addresses set aside)
  before the structural score, so an unchanged leaf with no strings or panic
  locations still finds its copy (`same-code:+1000`).
- `diff-c A B` without `--other` compares two functions of one binary and
  keeps callee names.
- `asm --from A --to B` works without an address; `field` names the
  functions its budgets stopped and how to raise them.

## Compatibility

Inputs remain x86-64 ELF and thin x86-64 Mach-O; `xref live` remains Linux
x86-64 only. The structured query and MCP operations are unchanged from
v0.5.0 except for the live `memscan` range and `watch` sample options. The
command reference, home-page recordings and live walkthrough were recorded
with this release's code before the tag.
